# 시민 대상 공개 사이트 개편 설계

작성일: 2026-09-21
대상: 청년노동자인권센터 공개 사이트
상태: 승인됨

## 1. 목적

이 개편의 최우선 목표는 처음 방문한 시민이 30초 안에 다음 세 가지를 이해하도록 만드는 것이다.

1. 청년노동자인권센터는 중소영세 제조업 청년노동자의 안전하게 일할 권리를 위해 활동한다.
2. 반도체고와 반도체산업은 현재 가장 깊이 만나고 있는 첫 현장이다.
3. 센터는 계획만 제시하는 조직이 아니라 학교 방문, 교사 조직화, 교육, 캠페인, 연구와 시민이 직접 사용할 수 있는 안전 도구 개발을 실제로 수행한다.

동아리 신청 전환은 유지하지만 공개 사이트의 최상위 목표로 두지 않는다. 시민에게 단체의 정체성과 현장성을 전달하고 신뢰를 형성하는 일을 먼저 둔다.

## 2. 현재 진단

현재 공개 사이트는 노동안전보건 교과서, 앱, 청소년노동안전동아리 등 지원사업의 산출물을 중심으로 구성돼 있다. 그 결과 다음 문제가 발생한다.

- 중소영세 제조업 청년노동자와 함께한다는 단체의 장기 정체성이 약하게 보인다.
- 6개 반도체고 현장 접촉, 교사 조직화, `일하는 열아홉` 4회 강좌, 기초연구, 커피차 캠페인 등 실제 활동이 드러나지 않는다.
- 지원사업이 끝나거나 산출물이 달라지면 현재의 사업 분류도 함께 낡게 된다.
- 아름다운재단의 역할과 센터 자체 활동의 관계가 명확히 설명되지 않는다.
- 공통 헤더가 `<main>` 요소를 즉시 닫아 각 페이지의 핵심 콘텐츠가 메인 랜드마크 밖에 놓인다.
- 외부 폰트 CSS가 첫 렌더링 경로에 있고 정적 자산 캐시 정책이 없다.
- 저장소에는 약 7.5MB의 `hero.jpg`가 있으나 현재 공개 페이지에서 사용되지 않는다.

## 3. 서버 실물 확인 선행 조건

현재 확인된 운영 상태는 다음과 같다.

- 운영 서버의 `/admin/login.php`가 응답한다.
- `/committee/` 신청 폼과 데이터베이스 처리가 동작한다.
- 구 사이트 경로 `/board.php`, `/community/`는 404를 반환한다.
- 로컬 백업 `htdocs_backup/younglabor_backup`에는 `index.php`가 없고 Git 메타데이터도 손상돼 있어 완전한 원본으로 사용할 수 없다.

따라서 구현 착수 전에 FTP 또는 SSH로 운영 서버의 실물을 읽기 전용으로 확인해야 한다. 확인 범위는 다음으로 고정한다.

1. 운영 문서 루트의 파일 목록과 관리자·게시판 관련 PHP 파일
2. 운영 코드와 현재 저장소 파일의 해시 차이
3. 관리자, 신청, 방문 통계, 게시판 관련 데이터베이스 테이블 구조
4. 업로드 디렉터리와 파일 보존 규칙
5. 배포 방식, PHP 버전, 활성 Apache 모듈, 파일 권한
6. 복구 가능한 서버 백업과 데이터베이스 백업의 존재 여부

이 조사에서는 `.env`와 비밀번호 같은 비밀값을 저장소로 복사하지 않는다. 파일명, 구조, 버전, 해시와 필요한 설정 키의 존재만 기록한다. 서버 코드와 데이터베이스를 백업하고 로컬 저장소와의 차이를 정리하기 전에는 관리자·신청 기능을 덮어쓰거나 삭제하지 않는다.

구 게시판 코드를 발견하면 보안 상태와 현재 PHP 호환성을 평가한 뒤 재사용 여부를 결정한다. 코드가 없거나 신뢰할 수 없으면 활동게시판·언론보도·자료실에 한정된 새 통합 콘텐츠 관리 기능을 구현한다. 이 결정은 추측이나 손상된 로컬 백업에 근거하지 않는다.

## 4. 메시지와 포지셔닝

### 핵심 문장

> 제조업 청년노동자들의 안전과 노동권을 지킵니다.

### 보조 설명

> 반도체고와 반도체산업 현장은 지금 가장 깊이 만나고 있는 첫 현장입니다. 학교와 일터에서 위험을 알고 말할 수 있도록 현장, 교육, 안전 도구, 연구를 연결합니다.

`처음 일하는 열아홉의 몸을 지킵니다`는 교육·캠페인 콘텐츠의 제목으로 사용한다. 사이트 전체의 대표 문장에서는 특정 나이만 지원하는 단체로 오해되지 않도록 `청년`과 `제조업`을 함께 명시한다.

문장은 기관 내부 용어보다 사람이 겪는 변화와 현장 장면을 우선한다. `조직화`, `MSDS` 같은 용어를 사용할 때는 시민이 이해할 수 있는 짧은 설명을 붙인다.

## 5. 정보 구조

### 전역 메뉴

1. 우리는 누구인가
2. 우리가 하는 일
3. 활동게시판
4. 언론보도
5. 자료실
6. 안전 도구
7. 함께하기

동아리 신청은 기능을 유지하고 `현장 조직` 및 `함께하기` 화면에서 연결한다. 시민 홍보가 주목적인 전역 메뉴에서는 단체 이해 흐름을 우선한다.

### 홈 화면 순서

1. **정체성** — 핵심 문장, 보조 설명, `우리는 누구인가` 링크
2. **현장에서 무슨 일이 있었나** — 최신 활동게시물 3건
3. **왜 이 일을 하는가** — 제조업 청년노동자의 산재와 안전교육 공백을 세 문단 이내로 설명
4. **우리가 하는 일** — 현장 조직, 교육, 안전 도구, 연구
5. **현장에서 쓰는 안전 도구** — SafeFactory와 기초 노동상담 소개 및 바로가기
6. **언론이 본 현장** — 최신 언론보도 3건과 원문 연결
7. **숫자로 보는 활동** — 출처를 확인할 수 있는 활동 수치만 표시
8. **함께하기** — 협력 문의, 활동 소식 보기, 동아리 신청
9. **함께하는 곳들** — 지원기관과 협력기관의 관계를 구분해 표시

통계 수치는 관리자 화면에서 임의로 편집하지 않는다. 확인 가능한 활동 기록에서 집계하거나 운영진이 근거 자료와 함께 코드에 반영한다. 근거가 없는 수치는 표시하지 않는다.

### 우리는 누구인가

현재 `단체소개` 페이지를 다음 흐름으로 바꾼다.

1. 단체의 정체성과 활동 대상
2. 왜 제조업 청년노동자인가
3. 왜 반도체고에서 시작하는가
4. 센터가 만드는 변화
5. 함께하는 사람과 협력기관

다른 단체와의 비교를 중심 메시지로 사용하지 않는다. 센터의 역할과 협력 관계를 독립적으로 설명한다.

### 우리가 하는 일

사업 산출물 대신 지속 가능한 활동 방식으로 분류한다.

| 갈래 | 포함 활동 | 시민에게 설명할 변화 |
| --- | --- | --- |
| 현장 조직 | 학교 방문, 교사 만남, 커피차 캠페인, 동아리 | 당사자와 지속적으로 만나 안전 문제를 발견하고 함께 말할 관계를 만든다. |
| 교육 | `일하는 열아홉`, `반도체란?` 교육자료 | 일을 시작하기 전에 위험을 알고 질문할 수 있게 한다. |
| 안전 도구 | SafeFactory, 기초 노동상담, 노동안전보건 교과서 | 학교와 일터에서 필요한 안전·노동 정보를 쉽게 찾고 사용할 수 있게 한다. |
| 연구 | 기초연구, 현장 조사, 보고서 | 경험을 근거로 만들고 교육·제도 개선에 연결한다. |

각 갈래는 관련 활동게시물과 연결해 계획과 실적을 함께 보여준다.

### 안전 도구 페이지

`안전 도구`는 센터가 제작 중인 서비스를 시민에게 소개하고 실제 서비스로 연결하는 독립 페이지다. 단순 외부 링크 모음이 아니라 어떤 문제를 누구와 해결하려는 도구인지 설명해 센터의 현장 활동과 기술 개발을 연결한다.

페이지 상단에는 다음 메시지를 사용한다.

> 현장에서 생긴 질문을, 누구나 사용할 수 있는 도구로 만듭니다.

> 청년노동자가 일을 시작하기 전에 위험을 배우고, 일하면서 생긴 노동 문제의 근거를 찾을 수 있도록 두 가지 서비스를 만들고 있습니다.

#### SafeFactory

- 주소: `https://safefactory.kr/`
- 표시 상태: 제작 중
- 대상: 반도체 분야 특성화고 학생과 교사, 산업안전을 배우려는 청년
- 소개 문구: `반도체와 산업안전을 질문하고 배우는 AI 학습 플랫폼`
- 설명: NCS 반도체 자료, 안전교육 자료, KOSHA 가이드와 MSDS를 한곳에서 검색하고 질문할 수 있게 한다. 학습, MSDS 검색, 공유질문, 학생 커뮤니티와 안전 뉴스 기능을 제공한다.
- 센터 활동과의 연결: `교육`과 `안전 도구` 활동의 결과물로 소개하고 관련 교육·학교방문 활동게시물을 함께 노출한다.
- 버튼 문구: `SafeFactory 살펴보기`

#### 기초 노동상담

- 주소: `https://laborconsult.vercel.app/`
- 표시 상태: 제작 중
- 대상: 임금, 퇴직금, 해고, 연차, 4대보험 등 기초 노동 문제를 확인하려는 청년노동자와 시민
- 소개 문구: `법령과 판례의 근거를 함께 보여주는 AI 노동상담·임금계산 도구`
- 설명: 근로기준법, 판례와 행정해석을 근거로 기초 노동상담 정보를 제공하고 28종의 임금 계산 기능으로 사용자가 자신의 상황을 먼저 정리하도록 돕는다.
- 주의 문구: `AI 답변과 계산 결과는 참고용이며 법적 효력이 없습니다. 중요한 사안은 노동상담기관이나 전문가에게 확인하세요.`
- 센터 활동과의 연결: 제조업 청년노동자의 일상적인 권리 문제를 지원하는 `안전 도구` 활동으로 소개한다.
- 버튼 문구: `기초 노동상담 사용해보기`

홈에서는 두 서비스의 이름, 한 문장 설명, `제작 중` 상태와 전용 페이지 링크만 보여준다. 상세 기능과 주의사항은 안전 도구 페이지에서 제공한다.

두 서비스는 iframe으로 삽입하거나 외부 데이터를 실시간으로 가져오지 않는다. 소개 내용과 링크를 사이트 자체 HTML로 렌더링해 외부 서비스 장애가 센터 사이트의 로딩과 안정성에 영향을 주지 않게 한다. 링크에는 실제 도메인을 함께 표시하고 같은 창에서 이동하게 한다. 이동 전에 `외부 서비스로 이동합니다`라는 의미가 링크 문구와 시각 표식으로 드러나야 한다.

외부 사이트의 로고나 화면 이미지는 원격 주소에서 직접 불러오지 않는다. 사용 권리가 확인된 로컬 자산만 최적화해 사용하며, 1차 공개에서는 텍스트와 센터 디자인 요소만으로 서비스 카드를 구성한다. 서비스의 공개 상태와 기능 설명은 코드에 명시적으로 관리하고 서비스 화면을 자동 수집하지 않는다.

안전 도구 페이지 하단에는 외부 서비스에서 별도의 개인정보처리방침과 이용약관이 적용됨을 알린다. `제작 중` 표시는 두 서비스가 정식 운영 기준을 충족하고 운영진이 제거를 승인할 때까지 유지한다.

### 함께하는 곳들

아름다운재단은 개별 사업 항목에서 분리하고 `지원` 관계로 명시한다. 홈 하단과 푸터에는 지원 연도와 사업명을 포함한 크레딧을 제공한다. 다른 단체는 실제 관계에 따라 `지원`, `협력`, `자문`을 구분한다. 모든 로고에는 텍스트 이름과 대체 텍스트를 제공한다.

## 6. 활동게시판·언론보도·자료실

### 목적과 범위

세 영역은 하나의 제한된 관리자 콘텐츠 기능을 공유한다. 일반 페이지 전체를 수정하는 범용 CMS가 아니라 `activity`, `press`, `resource` 세 유형의 게시물만 작성·수정·삭제·공개한다. 기존 관리자 인증과 CSRF 방어를 재사용하되 서버 실물 확인 후 계정과 세션 구조가 안전한 경우에만 연결한다.

공개 경로는 다음으로 고정한다.

- `/activity` — 활동게시판 목록
- `/activity/{slug}` — 활동게시물 상세
- `/press` — 언론보도 목록과 원문 연결
- `/resources` — 자료실 목록
- `/resources/{slug}` — 자료 설명과 다운로드 또는 외부 자료 연결
- `/media/{id}` — 공개 활동게시물의 대표 이미지
- `/downloads/{id}` — 공개 자료의 첨부파일 다운로드
- `/admin/content` — 유형별 관리자 목록
- `/admin/content-edit` — 작성·수정 화면

### 공통 게시 상태와 본문

세 유형은 `draft`와 `published` 상태만 사용한다. 공개 화면은 `published`만 조회한다. 제목, 요약, 본문은 일반 텍스트로 저장하고 출력 시 이스케이프한 뒤 문단과 줄바꿈만 변환한다. HTML 편집기와 임의 임베드 코드는 제공하지 않는다.

수정 화면은 revision 값을 사용해 먼저 저장된 다른 관리자의 변경을 덮어쓰지 않는다. 저장 충돌이 발생하면 기존 입력을 보존하고 새로고침 후 다시 확인하도록 안내한다.

### 활동게시판

활동게시물은 제목, 고유 슬러그, 활동일, 요약, 본문, 대표 이미지 1장, 작성·수정 시각을 가진다. 본문은 센터가 실제로 수행한 캠페인·교육·현장 활동을 시민에게 설명한다. 대표 이미지는 선택 사항이며 JPEG, PNG, WebP만 허용한다. 서버는 이미지 여부와 크기를 해석하고 최대 5MiB, 최대 6000 x 6000 픽셀로 제한한 뒤 최대 변 1600픽셀의 WebP로 다시 인코딩한다. 이미지에는 대체 텍스트가 필요하다.

학생 등 식별 가능한 미성년자의 얼굴은 기본적으로 사용하지 않는다. 필요한 동의를 확인하지 않은 이미지는 업로드하지 않는다는 관리자 안내를 입력 화면에 표시한다. 학교별 태그, 다중 사진, 동의 기록 저장과 작성자별 권한은 이번 범위에서 제외한다.

### 언론보도

언론보도는 제목, 언론사, 보도일, 짧은 소개, HTTPS 원문 URL을 가진다. 기사 전문과 원격 이미지를 복제하지 않는다. 공개 목록은 언론사·날짜·소개와 `원문 보기` 링크를 표시하고 외부 이동임을 알린다. 허용되지 않은 URL 스킴, 사용자 정보가 포함된 URL, 로컬·사설 네트워크 주소는 저장하지 않는다.

### 자료실

자료는 제목, 분류, 설명, 게시일과 하나의 첨부파일 또는 HTTPS 외부 자료 URL을 가진다. 분류는 `교육자료`, `연구보고서`, `안내서`, `기타`로 제한한다. 첨부파일과 외부 URL을 동시에 등록하지 않으며 둘 중 하나는 반드시 필요하다.

첨부파일은 PDF, HWP, HWPX, DOC, DOCX, XLS, XLSX, PPT, PPTX, ZIP으로 제한하고 최대 20MiB로 설정한다. 확장자, 서버가 확인한 MIME, 파일 시그니처를 함께 검사한다. 실제 파일은 웹 문서 루트 밖의 `CONTENT_STORAGE_PATH`에 무작위 이름으로 저장한다. 다운로드는 PHP가 게시물 공개 상태를 확인한 뒤 `Content-Disposition: attachment`, 안전한 원본 파일명, `X-Content-Type-Options: nosniff`를 제공한다. 브라우저에서 실행될 수 있는 HTML, SVG, JavaScript와 실행 파일은 허용하지 않는다.

### 통합 데이터 구조

`content_posts`는 유형, 제목, 슬러그, 요약, 본문, 게시 기준일, 공개 상태, 언론사, 원문 URL, 자료 분류, 작성자, revision, 공개·생성·수정 시각을 저장한다. 유형별로 사용하지 않는 필드는 null로 두고 저장 서비스가 필요한 조합을 검증한다.

`content_files`는 게시물 식별자, `cover` 또는 `attachment` 용도, 무작위 저장명, 원본 표시명, MIME, 바이트 크기, 이미지 너비·높이와 대체 텍스트를 저장한다. 활동게시물에는 cover 최대 1개, 자료에는 attachment 최대 1개만 연결한다. 언론보도에는 파일을 연결하지 않는다.

### 관리자 작업

관리자는 유형별 목록에서 검색·상태 필터·작성·수정·공개·삭제를 수행한다. 모든 변경 요청은 POST와 CSRF 검증을 사용하고 작성자 식별자는 세션에서 가져온다. 파일 저장과 DB 저장은 실패 시 부분 데이터가 남지 않도록 조정하며, 새 파일 저장에 실패하면 게시물 변경을 적용하지 않는다. 게시물 삭제 후 파일 삭제가 실패하면 관리 로그에 남기고 재처리 대상으로 표시한다.

## 7. 기술 구조

현재 Apache/PHP 기반의 서버 렌더링 구조를 유지한다. 공통 헤더는 `<main>`을 열고 공통 푸터가 닫도록 수정해 모든 공개 콘텐츠를 올바른 랜드마크 안에 둔다.

페이지별 데이터 흐름은 다음과 같다.

- 정적 소개·사업 내용: PHP 템플릿에서 즉시 렌더링
- 활동게시판·언론보도·자료실: 공개된 유형별 게시물을 데이터베이스에서 읽어 서버 렌더링
- 홈 최신 콘텐츠: 활동게시물과 언론보도를 각각 최신 3건만 읽어 서버 렌더링
- 관리자 작성: 인증된 POST 요청, CSRF 검증, 유형별 서버 검증 후 저장
- 자료 다운로드와 활동 이미지: 공개 상태와 파일 메타데이터를 확인하는 PHP 응답을 통해 제공

콘텐츠 조회 실패가 홈 전체 장애로 번지지 않게 한다. 홈에서는 해당 섹션에 짧은 안내와 각 목록 링크를 표시하고 나머지 정적 콘텐츠를 정상 렌더링한다. 관리자 저장 실패 시 입력 내용을 유지하고 원인을 일반 사용자가 이해할 수 있는 메시지로 보여주며, 상세 오류는 서버 로그에만 남긴다.

대표 이미지 응답은 게시물 공개 상태를 확인한 뒤 `ETag`와 장기 브라우저 캐시 헤더를 제공한다. 자료 다운로드 응답은 범위 요청을 지원하고, 파일 자체가 바뀌지 않는 한 재전송을 줄일 수 있는 검증 헤더를 제공한다.

## 8. 로딩 성능

성능 개선은 시각적 개편과 함께 적용한다.

- 1차 개편에서는 외부 Pretendard 요청을 제거하고 운영체제의 한국어 시스템 글꼴을 사용한다. 별도 웹폰트는 후속 시각 검증에서 꼭 필요하다고 판단될 때만 추가한다.
- 공개 페이지 스타일은 하나의 공통 CSS에 통합하고 현재 페이지 안에 흩어진 인라인 스타일을 옮긴다. 관리자 스타일은 공개 페이지와 합치지 않는다.
- 이미지에는 명시적 너비와 높이, `srcset`, `sizes`, WebP 또는 AVIF 변형을 제공한다.
- 첫 화면 핵심 이미지만 우선 로딩하고 하단 이미지는 지연 로딩한다.
- 현재 사용하지 않는 `hero.jpg`는 새 홈에서도 사용하지 않고 배포 자산에서 제거한다. Git 이력으로 원본을 보존한다.
- 버전이 붙은 CSS, 폰트, 이미지에는 장기 캐시를 적용하고 HTML과 동적 응답은 짧은 캐시 또는 비캐시 정책을 사용한다.
- Apache에서 가능한 압축을 활성화하되 활성 모듈을 확인한 뒤 조건부 설정으로 배포한다.
- 핵심 콘텐츠는 JavaScript 없이도 읽고 이동할 수 있게 서버에서 렌더링한다.
- 동작 애니메이션은 `prefers-reduced-motion`을 존중한다.

운영 환경 모바일 75백분위 목표는 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하로 둔다. 구현 전후 같은 페이지·같은 조건에서 Lighthouse와 실제 응답 크기를 기록한다.

## 9. 접근성 및 검색 노출

- 페이지마다 하나의 명확한 `<h1>`과 순서가 맞는 제목 구조를 사용한다.
- 키보드로 메뉴, 링크, 폼, 관리자 작성 화면을 모두 사용할 수 있게 한다.
- 포커스 표시와 텍스트 대비를 WCAG AA 수준으로 유지한다.
- 모바일 메뉴 버튼의 열림 상태를 `aria-expanded`로 전달한다.
- 활동 사진은 대체 텍스트를 제공하고 장식 이미지는 빈 대체 텍스트로 처리한다.
- 페이지별 제목, 설명, 정규 URL, Open Graph 메타데이터를 제공한다.
- 활동게시물 상세 페이지에는 활동일과 수정일을 표시하고 구조화된 `Article` 데이터를 제공한다.
- 언론보도 원문 링크와 외부 자료 링크에는 외부 이동 여부와 실제 도메인을 표시한다.
- 자료 다운로드 링크에는 파일 형식과 크기를 텍스트로 제공한다.
- 안전 도구의 외부 링크에는 서비스 이름, 실제 도메인, 외부 이동 여부를 보조기술이 이해할 수 있는 텍스트로 제공한다.

## 10. 검증 기준

### 메시지 전달

- 센터 활동을 잘 모르는 시민 5명에게 5초 동안 홈 첫 화면을 보여준 뒤 `누구를 위해 무엇을 하는 단체인가`를 묻는다.
- 5명 중 4명 이상이 `제조업 청년노동자`, `안전하게 일할 권리`, `현장 활동` 중 두 가지 이상을 언급하면 핵심 메시지가 전달된 것으로 본다.

### 기능

- 모든 공개 경로와 메뉴 링크가 데스크톱·모바일에서 정상 동작한다.
- 기존 `/admin/login.php`와 `/committee/` 기능 및 저장 데이터가 유지된다.
- 활동게시물 작성·임시저장·공개·수정·삭제와 대표 이미지 검증이 동작한다.
- 언론보도 작성과 안전한 HTTPS 원문 연결이 동작한다.
- 자료 작성과 허용된 파일의 외부 저장·다운로드 또는 HTTPS 외부 자료 연결이 동작한다.
- 임시저장된 세 유형의 게시물이 공개 목록·상세·다운로드에서 노출되지 않는다.
- 데이터베이스 장애가 홈 전체 500 오류로 이어지지 않는다.
- 홈과 안전 도구 페이지의 두 서비스 링크가 각각 `https://safefactory.kr/`, `https://laborconsult.vercel.app/`로 정확히 연결된다.
- 배포 전 외부 링크의 HTTP 응답을 확인하되, 외부 서비스 장애는 센터 사이트 배포 실패나 페이지 렌더링 실패로 처리하지 않고 점검 결과에 경고로 기록한다.

### 품질

- HTML 랜드마크와 제목 구조를 자동·수동 검사한다.
- 키보드 이동, 화면 확대, 모션 감소 설정을 검사한다.
- 저장형 XSS, CSRF, 파일 업로드 우회, 비공개 글 노출 회귀 검사를 수행한다.
- 운영과 같은 PHP 버전에서 문법 검사와 주요 페이지 HTTP 응답 검사를 수행한다.
- Lighthouse와 정적 자산 전송량을 변경 전후로 비교한다.

## 11. 출시 원칙

서버 실물과 데이터베이스 구조를 확인하고 백업을 확보한 뒤 구현한다. 공개 페이지의 정적 구조와 통합 콘텐츠 관리 기능은 별도 변경 단위로 개발·검토할 수 있지만, 운영 반영 전에는 하나의 스테이징 환경에서 기존 관리자·신청 기능과 함께 검증한다.

운영 반영에는 데이터베이스 마이그레이션의 적용·되돌리기 절차, 업로드 보존 확인, 주요 URL 점검, 이전 버전 복구 절차를 포함한다. 운영 데이터에 직접 실험용 글이나 이미지를 넣지 않는다.

## 13. 후속 보안·배포 백로그

다음 항목은 이번 정보 구조·성능 개편과 분리해 보관한다. 서버 조사에서 즉시 위험이 확인되면 공개 사이트 배포보다 먼저 처리한다.

1. 배포 압축 해제·복사·삭제 실패 시 즉시 실패 처리하고 성공 응답을 금지한다.
2. 커밋 식별, 배포 직렬화, 스테이징 검증, 원자적 전환과 롤백을 도입한다.
3. 초기 관리자 생성에서 CSRF 실패 시 처리를 즉시 중단한다.
4. CSV 내보내기의 수식 주입을 방지한다.
5. 관리자 비활성화·삭제·비밀번호 변경 시 기존 세션을 즉시 무효화한다.
6. 완전하고 순서가 있는 데이터베이스 기준 스키마와 마이그레이션을 저장소에 포함한다.
7. CSP 등 보안 헤더를 추가하고 로그와 비밀 파일을 문서 루트 밖으로 이동한다.
