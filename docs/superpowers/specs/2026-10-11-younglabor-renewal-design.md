# 청쎈 사이트 전면 개편 설계

작성일: 2026-10-11
상태: 사용자 검토 대기 — 제품 코드 구현 전

## 1. 기준과 목표

사용자가 지정한 `work-2026-10-11-1936-청년노동자인권센터-사이트-구축기획안.md`를 이번 개편의 기준으로 삼는다. 연결된 2125 교육프로그램 기획안과 2144 인큐베이팅 지원사업 기획안도 확인했다. 원본 Obsidian 문서는 수정하지 않는다.

중소·영세 제조현장 청년노동자와 일터로 진입하는 직업계고 학생·졸업생이 청쎈의 활동을 이해하고 실제 프로그램·자료·담당자에게 연결되는 사이트를 만든다. 시민·언론·교사·협력단체가 글과 협력 경로를 찾을 수 있게 한다. 기존 문서의 일반 대중 우선 설정보다 이번 기획안의 핵심 대상을 우선한다.

이번 요청을 전면 개편의 작업 지시로 해석한다. 기획안에서 미확정으로 남긴 모집 상태·공개 자료·완료 성과는 임의로 확정하지 않는다. 화면 구현은 미확정 상태에서도 가능하도록 설계한다.

## 2. 현재 구조와 접근 방식

- 프레임워크 없는 PHP 8+, MySQL/MariaDB, 공통 header/footer, 단일 공개 CSS, Apache 경로 재작성 구조다.
- `ContentRepository`, `ContentManager`, `ContentValidation`, `ContentStorage`가 활동·언론보도·자료를 관리한다. 관리자 인증, CSRF, 수정 충돌 감지, 파일 검증이 있다.
- 현재 사업 분류는 교육·도구·연구 세 축이고 헤더는 일곱 경로를 노출한다. 새 기획의 네 메뉴·네 사업축과 다르다.
- 문의 API는 이름과 이메일을 필수로 요구하며 DB 저장과 SMTP 전송을 처리한다. 새 최소 입력 요건에 맞춰 수정해야 한다.
- `CLAUDE.md`의 자동 테스트 없음 설명과 달리 `tests/`에 PHP 단위 테스트, MySQL 통합 테스트, HTTP 검증이 있다. 실제 테스트 파일을 기준으로 검증한다.
- 작업 시작 전 이미 변경된 `CLAUDE.md` 및 미추적 운영·문서 파일이 있다. 개편 변경과 구분해 보존한다.

**추천: 기존 PHP·관리자 기능을 확장한다.** 인증·업로드·배포 구조를 유지하면서 공개 화면과 콘텐츠 모델을 개편할 수 있다. 정적 화면만 교체하는 방식은 사업·모집 운영 요건을 충족하지 못하고, 새 프레임워크로 재작성하는 방식은 인증·파일·배포 이관 범위가 커진다.

## 4. 공개 화면과 시각 방향

브랜드는 **청쎈 + 청년노동자인권센터**를 함께 표기한다. 로고 파일이 없으면 텍스트 워드마크를 사용한다. 기존 브랜드 자료의 라임 `#CEE84F`, 퍼플 `#430086`, 블랙·화이트, 큰 제목, 얇은 구획선과 넉넉한 여백을 이어간다. 경고 테이프·PPE 같은 산업안전 상징은 추가하지 않는다. 본문은 읽기 편한 길이와 줄간격을 확보하고 모바일에서는 제목 크기를 조정한다.

홈 순서:

1. 네 메뉴의 공통 헤더와 모바일 메뉴.
2. “일하는 청년이, 권리를 가진 주체로”와 대상·목적 설명. 모집 중인 활동이 있으면 참여 활동으로, 없으면 사업 목록으로 연결.
3. 청쎈이 만나는 제조현장 청년과 학교에서 일터로 향하는 청년 설명.
4. 네 사업축 카드와 실제 상태·다음 행동.
5. 하반기 연속강좌 상세 연결. 확인되지 않은 모집은 신청 가능으로 표시하지 않는다.
6. 청년과노동 최신 공개 글 최대 세 편, 작성 주체·날짜 표시.
7. 새 소식과 연락·문의.
8. 정식 명칭, 운영 연락처, 지원 표기, 개인정보 안내를 담은 푸터.

실제 활동 사진·후기·성과 수치를 생성하지 않는다. 확인된 포스터를 사용할 경우 이미지 안의 정보를 HTML 본문에도 제공한다. 사진이 없으면 타이포와 추상 도형으로 화면을 구성한다. 공개 자료·소셜·연락처는 확인된 값만 사용한다.

지원사업 탭은 서로 다른 URL로 이동하는 링크형 탐색이다. 긴 탭 이름을 생략하지 않고 선택 상태와 키보드 초점을 구분한다. 자바스크립트 없이도 두 화면으로 이동할 수 있다.

## 7. 콘텐츠와 관리자 설계

기존 테이블을 삭제하거나 기존 글을 일괄 공개하지 않는 추가 마이그레이션을 제공한다.

- `content_posts`의 기존 activity/press/resource 데이터는 유지한다. 청년과노동용 article, 공지·모집용 notice 유형을 추가한다.
- 글에는 공개 작성 주체, 글 분류, 연결 사업축, 관련 프로그램 ID, 홈 노출 여부를 추가한다. 로그인 관리자 ID와 공개 작성자 표기는 구분한다.
- 사업·지원사업·프로그램은 별도 구조화 테이블에서 관리한다. 사업은 제목·slug·대상·설명·제공 범위·상태·행동 경로·공개 여부, 지원사업은 연도·차수·지원 명의와 단위사업 참조를 가진다.
- 프로그램은 제목·소개·사업축·장소·비용·신청 URL·접수 상태·마감·문의·주최·지원·공개 여부를 가진다. 회차는 프로그램 ID·순서·일시·강사·제목·설명·참여 방식·패널 안내를 가진다.
- 사업 상태는 준비 중/모집 중/운영 중/종료, 프로그램 접수는 확인 대기/모집 중/마감으로 관리한다. 공개 여부(draft/published)와 상태는 별도 값이다.
- 준비 중은 목적·진행 상황과 자세히 보기, 모집 중은 실제 신청, 운영 중은 이용 안내·자료, 종료는 실제 기록으로 연결한다. 자료가 없으면 다운로드·기록 버튼을 숨긴다.
- 관리자는 글·사업·지원사업·프로그램·회차를 편집하고 홈 노출과 모집 종료를 처리할 수 있다. 화면에 상태와 제공 경로를 함께 보여준다.
- 기존 인증·CSRF·revision 충돌 감지·파일 검증을 확장된 유형에도 적용한다. 본문은 기존 안전한 텍스트 출력 방식을 유지한다.
- 기획안 내용은 중복 실행해도 덮어쓰지 않는 초기 데이터 입력 절차로 제공한다. 기존 동아리 설정은 초기 단계에서 보존하고 관리 데이터 전환 시 하나의 원본으로 통합한다.

새 스키마가 적용되지 않았으면 DB 의존 화면은 준비 상태를 보여주며 SQL 오류나 초안·개인정보를 출력하지 않는다. DB 장애 시 홈·기본 소개는 표시하고 목록은 일시적인 조회 오류로 안내한다. 자료가 없는 상태와 조회 실패를 구분한다.

## 8. 문의 흐름

필수 입력은 문의 유형, 답변받을 이메일, 문의 내용이다. 이름은 선택 입력이다. 초기 범위는 연락 방법을 이메일 하나로 정해 기존 메일·관리자 업무와 연결한다. 회사명·사건 자료·첨부는 받지 않는다.

API·DB·메일·관리자 표시를 함께 수정해 선택 이름과 문의 유형을 처리한다. 서버 입력 검증과 글자 수 제한을 적용한다. 접수는 비공개 문의함에 저장한다. DB 저장 성공 여부와 담당자 메일 알림 결과를 구분하고, 실제 저장 성공 없이 완료를 표시하지 않는다. DB 실패는 입력을 보존하고 재시도·이메일 대체 경로를 제공한다. 저장 성공·메일 알림 실패는 관리자 문의함 접수로 안내하고 재제출을 유도하지 않는다.

운영 연락처는 기획안에서 제공한 이메일을 사용한다. 응답 시간·24시간 상담·전문가 자동 연계는 약속하지 않는다. 개인정보 안내는 실제 수집 항목·이용 목적을 설명하고, 보관 기간·열람 담당 등 확정되지 않은 운영 정책은 공개 검수에서 확인한다. 사이트 개편으로 법적 적합성을 확정했다고 표시하지 않는다.

## 9. 구현 경계와 데이터 흐름

공통 화면은 header/footer/CSS를 사용한다. 사업 데이터 조회·상태별 행동 판정, 글 조회·분류, 프로그램·회차 조회, 관리자 저장·검증을 작은 단위로 분리한다. 공개 페이지는 published 데이터만 조회하고 정렬·페이지네이션·분류 필터를 제공한다.

콘텐츠 저장 → 검증 → 인증된 관리자 저장 → 공개 조회 → 홈/사업/게시판 표시의 흐름을 따른다. 관련 모집 안내는 프로그램 상세 링크를 참조해 일정·신청 상태를 중복 저장하지 않는다. 기존 파일 응답과 다운로드 권한은 그대로 활용한다.

이번 범위는 반응형 공개 사이트와 기본 콘텐츠 운영까지다. 앱 자체 개발, AI 상담 서비스 구현, 회원 계정, 공개 자유게시판·댓글, 자동 전문가 매칭은 별도 개발 과제로 남긴다. 외부 신청서를 직접 수정하거나 제출하지 않는다.

## 10. 검증과 완료 기준

1. 네 메뉴, 두 사업 탭, 네 사업 상세, 강좌 상세, 청년과노동·게시판 목록/상세가 동작한다. 잘못된 slug는 404, 이전 주소는 대응 화면으로 연결된다.
2. 모든 강좌 연결이 같은 상세로 이동하며, 네 날짜·강사·방식·장소·주최·지원·신청 주소가 일치한다. 3회차 현장 참여와 확인되지 않은 완료 성과가 없다.
3. 상태별 버튼, 모집 마감 경계, 초안 비노출, 입력 검증, 수정 충돌, 관련 콘텐츠 연결을 의미 있는 단위 테스트로 확인한다.
4. 테스트용 MySQL DB에서 기존 데이터 보존, 새 스키마, 사업·프로그램·글 발행과 수정·종료, 파일 권한을 통합 검증한다. 운영 DB로 통합 테스트하지 않는다.
5. PHP 문법 검사와 기존 관련 회귀 테스트를 실행한다. 메뉴·카피의 기존 계약은 새 기획에 맞춰 갱신하고 파일·인증·문의·보안 계약은 유지한다.
6. HTTP로 신규·구 경로, canonical, 한 개의 h1/main, DB 장애와 빈 목록, 외부 링크, 모집 마감을 확인한다.
7. 모바일·데스크톱에서 줄바꿈·탭·카드·폼을 확인하고 키보드 메뉴, 초점, 라벨, 입력 오류와 완료 메시지를 검수한다.
8. 실제 문의 발송을 테스트할 때는 운영 담당자에게 도착하는 외부 발송을 별도 승인 없이 수행하지 않는다. 로컬 대역과 관리자 저장 검증으로 개발 확인을 수행한다.

사용자 조사 목표는 기획안대로 목표 이용자 5명 중 4명이 모바일에서 단체의 대상과 실제 참여·문의 경로를 1분 안에 찾는 것이다. 개발 검증과 실제 사용자 조사 결과는 구분해 보고한다.

로컬에서 검토 가능한 구현, 마이그레이션·초기 데이터 절차, 테스트 결과, 운영 공개 전 확인 항목을 인계한다. main push가 자동 배포를 실행하므로 구현 검토가 끝나기 전 운영 배포를 유발하는 push는 수행하지 않는다.
