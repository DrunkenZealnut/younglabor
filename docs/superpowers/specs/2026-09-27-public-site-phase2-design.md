## 1. 목적

1. **청소년노동안전동아리를 폐기하고 바이브코딩동아리 모집으로 전환한다.** 사이트에 남은 옛 동아리 신청 기능과 문구를 걷어내고, 새 모집의 소개·신청 동선을 만든다.
2. **1차 개편 이후 남은 빈틈을 메운다.** 비어 있는 활동게시판·언론보도·자료실을 채우고, 재단 크레딧과 검색 노출 기본값을 바로잡는다.

1차 원칙은 유지한다. 단체의 정체성과 현장성을 먼저 전하고, 동아리 모집은 그 현장성을 보여주는 **최근 현장 활동**으로 둔다. 전역 메뉴와 `우리가 하는 일` 3갈래(교육·안전 도구·연구, PR #8)는 바꾸지 않는다. 마감(10-15)까지만 홈에서 모집을 눈에 띄게 알린다.

### 4.2 저장된 신청 데이터 — D3 안내 후 파기

사실관계: 옛 폼은 동의 절차 없이 이름·연락처·학교·전공·학년·이메일·참여동기를 받았고, 이용 목적으로 안내한 것은 "검토 후 입력하신 연락처로 안내드리겠습니다"뿐이다. 따라서 안내는 **신청 결과 통지**의 범위로 한정하고, 안내 직후 파기한다.

1. 관리자 화면에서 **건수만** 확인한다. 행 내용은 저장소·문서·메신저로 옮기지 않는다. 0건이면 5번으로 간다.
2. 신청 때 받은 휴대전화로 1회 문자를 보낸다(이메일만 있으면 이메일). 초안:
   > [청년노동자인권센터] 신청해 주신 청소년노동안전동아리는 운영하지 않게 되어 알려드립니다. 대신 AI로 나만의 앱을 만드는 바이브코딩동아리를 10월 15일까지 모집합니다. younglabor.kr/club 에서 확인해 주세요. 보내주신 신청 정보는 이 안내 뒤 모두 삭제합니다.
3. 재발송·추가 홍보는 하지 않는다. 답장으로 받은 문의에는 답하되 새 정보를 모으지 않는다.
4. 발송 직후 관리자 화면의 일괄 삭제(`admin/api/committee-action.php` delete)로 모든 행을 지운다. 이때 다음도 함께 지운다.
   - 관리자 메일함의 신청 알림 메일 (`api/committee.php`가 신청 내용 전체를 보냈다)
   - CSV로 내보낸 파일이 있으면 그 파일
5. 파기 기록은 일시·건수·방법만 남긴다. 운영 백업(`~/.yl-backups`의 2026-09-21 DB 백업, 문서 루트 `backup/` 아카이브)에도 신청 행이 들어 있다. 새 기준 백업을 만든 뒤 이전 백업을 폐기할지, 보존 기한을 정해 둘지 기록한다.

### 4.3 관리자 기능과 테이블 — 3단계

`committee_applications`를 읽는 코드가 남아 있는 동안 테이블을 지우면 관리자 대시보드가 깨진다. 따라서 코드와 테이블을 한 변경 단위로 정리한다.

- 코드 제거: `admin/helpers.php` 사이드바 `동아리 신청` 메뉴와 대기 건수 뱃지, `admin/dashboard.php`의 신청 집계·최근 신청, `admin/committee.php`, `admin/api/committee-action.php`
- 테이블: `database/migrations/20261012_drop_committee_applications.sql`. 파기 목적이므로 되돌리기는 실행 직전에 보관한 `SHOW CREATE TABLE` 출력(스키마만, 행 없음)으로 빈 테이블을 다시 만드는 절차로 대신한다
- 파일: `admin/committee.php`, `admin/api/committee-action.php`, `api/committee.php`를 저장소에서 지운다. 운영의 prune이 꺼져 있으면 운영 파일도 수동으로 지운다(`backup/`·`.env`·업로드 경로 보호 규칙 유지). `committee/index.php`(301)는 남긴다

학생 문구에는 노동안전을 앞세우지 않는다(3월 모집 실패의 교훈). 시민·교사 문구에서 "만들며 익히는 노동안전"을 설명하고, 활동 과정에서 노동안전 소재의 앱(현장 안전 체크, MSDS 찾기 등)을 제안한다는 점을 밝힌다.

### 5.3 사이트 접점

| 위치 | 모집 중 (~10-15) | 마감 후 |
|---|---|---|
| 홈 알림 띠 (히어로 바로 아래) | `바이브코딩동아리 모집 중 · 10월 15일 마감` + `자세히 보기` → `/club` | 자동으로 숨김 |
| 홈 `함께하기` 버튼 | `바이브코딩동아리 신청` → `/club` | `바이브코딩동아리 소식` → `/club` |
| `/club` (신설) | 소개·신청 안내·외부 신청 링크 | "모집이 마감되었습니다" + 활동게시판 연결 |
| 활동게시판 | 모집 안내 글 1건 | 활동 기록 연재 |

알림 띠는 히어로 아래에 둔다. 단체 정체성을 먼저 보여준다는 1차 원칙을 지키기 위해서다. 전역 메뉴와 `우리가 하는 일` 갈래에는 동아리를 추가하지 않는다(PR #8 결정 유지).

모집 상태는 **서버가 마감일로 판단한다.** 마감일 당일 23:59:59(Asia/Seoul)까지 모집 중으로 보고, 운영자가 잊어도 지난 모집이 남지 않게 한다. 마감일은 설정 한 곳에서만 관리하고, 연장하면 그 값만 바꾼다.

### 5.4 `/club` 페이지

`.htaccess`의 확장자 없는 URL 규칙(`/club` → `club.php`)을 그대로 쓴다. 새 rewrite 규칙은 필요 없다. 같은 이름의 `club/` 디렉터리는 만들지 않는다.

1. **제목** `바이브코딩동아리` / 부제 `나도 개발자! — 반도체고 청소년과 함께하는 3개월`
2. **무엇을 하나요**: AI에게 말로 설명하며 나만의 앱 만들기. 예시 4종 카드
3. **누가 참가하나요**: 반도체고등학교 재학생, 코딩 경험 없어도 됨
4. **무엇을 지원하나요**: 러버블(Lovable) 이용 지원, AI 전문가 자문. 이용 방식(D8): "러버블 계정은 센터가 준비해 안내합니다. 만 18세 미만 참가자는 보호자 동의가 필요합니다."
5. **왜 센터가 하나요** (시민·교사용, 3문장 이내): 학교가 제공하기 어려운 AI 코딩 경험 → 필요한 도구를 스스로 만들며 일과 안전을 다시 보는 계기 → 올해 모델을 만들고 내년에 넓힘
6. **신청하기**: 마감일, 심사 가능성, 결과 안내 방법 + `신청서 작성하기 ↗`. 도메인 `zealot-survey.vercel.app`과 외부 이동 표시는 `tools.php`의 외부 링크 규칙과 같게 한다
7. **선생님께**: 담당교사 협력 문의 → 홈 `#contact` 문의 폼
8. **지원 표기**: 기존 `.sponsor-box` 로고 문장형 재사용

신청 폼은 사이트에 다시 만들지 않고 iframe도 쓰지 않는다. 외부 신청서가 동의 문구와 저장소를 갖고 있으므로 사이트는 소개와 연결만 맡는다(1차: 외부 서비스 장애가 사이트에 번지지 않게).

메타: `<title>바이브코딩동아리 모집 - 청년노동자인권센터</title>`. 학생이 메신저로 공유할 것을 전제로 전용 `og:image`(1200×630)를 둔다(§9.2).

## 9. 표기·검색 노출

### 9.1 재단 크레딧 (D4)

- 사이트 표기: **`공익단체 인큐베이팅 지원사업`**. 연도가 없으므로 3개년(2026~2028) 지원 기간 내내 낡지 않는다.
- 출력 결과: 푸터 `지원 [아름다운재단 로고] 공익단체 인큐베이팅 지원사업`, 홈·소개 `공익단체 인큐베이팅 지원사업 · 아름다운재단 지원`.
- `/club`과 사업 소개 문단: 로고 문장형 `이 사업은 [아름다운재단 로고] 지원으로 진행됩니다.`
- `아름다운 재단`(띄어쓰기)과 `후원` 표기는 쓰지 않는다(`facts.forbidden`).
- kb `program.credit_line`(연도 포함)은 연도가 박히는 보고서·행사 산출물에 계속 쓴다. 사이트만 연도 없는 표기를 쓴다는 예외를 kb에 기록한다(§10).

### 9.2 검색 노출

- `robots.txt`: `User-agent: *` 허용, `Disallow: /admin/`, `Sitemap: https://younglabor.kr/sitemap.xml`
- `sitemap.xml`: 서버가 게시 상태를 보고 생성. draft 게시물은 넣지 않는다
- `og:image`: 사이트 기본 1종 + `/club` 전용 1종. BF 저장소 `/promo` og-banner 템플릿(kb 브랜드 하늘·노랑)으로 만든다. 사이트 본문의 라임 색과 다르지만, 이번에는 kb 브랜드를 따른다
- `/committee`는 301로만 남기고 sitemap에 넣지 않는다

### 9.3 협력기관 표기 확인

소개 페이지의 협력기관 3곳은 kb `facts.partners`(지역 협력: 대구노동세상·음성노동인권센터·인천청소년노동인권네트워크·우리동네노동권찾기, 공동기획: 서울청소년노동인권네트워크·사회적협동조합 해봄, 검수: 노동환경건강연구소 등)와 이름이 다르다. 1차 원칙("실제 관계에 따라 지원·협력·자문 구분")에 따라 대표가 목록과 관계를 확인한 뒤 정리한다. 확인 전에는 바꾸지 않는다.

## 11. 검증 기준

### 기능

- `/committee`, `/committee/`가 `/club`으로 301 이동한다. `api/committee.php`는 어떤 요청에도 410을 반환하고 DB에 쓰지 않는다.
- 공개 파일 전체에 §4.1 폐기 문구가 없다.
- 모집 판정: 2026-10-15 23:59:59(Asia/Seoul)에는 모집 중, 2026-10-16 00:00:00에는 마감. 마감이면 홈 알림 띠가 없고 `/club`이 마감 상태를 보여준다.
- `/club` 신청 링크가 `https://zealot-survey.vercel.app/RJXag60aMfMT`로 연결되고, 외부 이동과 도메인이 텍스트로 드러난다.
- 푸터·홈·소개의 크레딧이 §9.1과 일치하고 `2025`가 남지 않는다.
- `robots.txt`·`sitemap.xml`이 200을 반환하고, sitemap에 draft·`/committee`가 없다.
- 1차 기준(관리자 로그인, 콘텐츠 관리, 다운로드, 문의 API)이 회귀하지 않는다. `tests/*.test.php` 전체, `public-http-smoke.sh`, `public-accessibility.test.js`를 통과한다.

### 메시지

- 반도체고 재학생 연령대 3명 이상에게 `/club`을 모바일로 보여주고 "무엇을 하는 동아리이고 어떻게 신청하는가"를 묻는다. 모두가 "AI로 앱을 만든다"와 "신청서 링크"를 답하면 통과.

### 데이터

- 옛 신청 데이터 파기 기록(일시·건수·방법, 관리자 메일·CSV·백업 처리)이 남아 있다. 행 내용은 기록에 없다.
